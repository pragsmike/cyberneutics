## Key findings worth carrying forward

1. **The add-paper workflow had a real gap.** Step 4 of the original `papers/README.md` only updated the local README; the master bib in `references/README.md` is the actual discovery surface for agents reading from the top of the references tree. The 2019 and 2022 papers slipped through this gap and were invisible in the master bib for an unknown duration. Workflow now has explicit step 5 for master-bib registration.

2. **Frontmatter is genuinely useful for agent navigation.** With `topics:` lists on every paper, an agent can `Grep` for e.g. `topics:.*Kauffman` and immediately find the 2022 paper without reading 80 lines of summary. The frontmatter is the cheapest way to make the corpus selectable without loading bodies. Worth replicating in other reference clusters (e.g. `references/bradley-cyberneutics-references.md`'s constituents).

3. **Cite-which-paper-for-what tables save real tokens.** The chronology already had this info as scattered "Cite this when:" prose lines per paper. A 6-row table at the top of `papers/README.md` covers the same information in <40 lines. Replicate this pattern for any reference cluster with >3 related papers.

4. **MDPI is unreachable from this Cowork environment.** Akamai 403s every fetch, even with browser User-Agent headers. Subagents have additional restrictions on top — both their WebFetch and shell network access are denied independent of the parent's permissions. For future open-access acquisitions: ask mg to download manually as the default path; don't burn turns on retry loops. The chronology already lists working retrieval routes (oro.open.ac.uk, ResearchGate, cutter.com) but those failed too in this session.

5. **The chronology is now the navigation layer**, formally. The papers/README intro now points agents at it explicitly. This makes the chronology load-bearing — keep it in sync when adding papers, and watch the at-a-glance table for entry parity.

## Technical notes

- **MDPI is unfetchable from this environment.** Future open-access acquisitions: try `Bash curl -L -A "Mozilla/5.0 ..."` once in foreground; if 403, ask mg to download manually rather than escalating. Don't bother with a subagent for PDF acquisition — its capability set is more restricted than the parent's.
- **`pdftotext -layout` from `/mingw64/bin`** works on this system (Windows + bash via Git for Windows or similar). Output goes to a file readable by Read tool only if placed inside the repo working directory; `/tmp` paths are not Read-accessible. Pattern: `pdftotext -layout pdfs/foo.pdf .tmp.txt` (dotfile to keep it inconspicuous), Read it, then `rm` after extraction.
- **The historical prompt at `agent/prompts/claude-code-prompt-essay12-and-residuality.md` retains the old `The-Philosophy-of-Residuality-Theory` slug.** This is intentional — it's a frozen record of the original assimilation work. Don't update it.
- **Frontmatter convention**: lowercase YAML keys, kebab-case values where appropriate (`paper-extract`, `paper-summary`, `chronology`), comma-separated arrays in flow style for `topics`. Length_words is the raw `wc -w` count of the markdown body — useful for agent token budgeting.

## Watch-outs for successor

- **The chronology is now load-bearing.** When adding a paper, both the at-a-glance table AND the per-paper "What each piece adds" section need entries. Step 7 of the workflow names this; don't skip it.
- **The master bib is the discovery surface.** Step 5 of the workflow is non-negotiable — without it, the paper is invisible to agents reading from the top of `references/README.md`. This is the bug that caused the 2019 and 2022 papers to be missing for an unknown duration.
- **The arc-blurb counts papers.** When the count changes (paper added/removed), update both the count word and the arrow-chain description.
- **The Cite-which-paper-for-what table on `papers/README.md` is the lowest-token discovery layer.** If a new paper changes which paper to cite for which claim, update the table — that's where most agents will look first under the new structure.
- **See-also footers are mandated symmetric.** Every summary's footer must list every other summary in the directory plus the chronology file. Step 6 of the workflow.
