# Meta: Reflective Documentation

This directory contains documentation *about* the methodology's evolution, adoption, validation, and current project state - distinct from the methodology itself (`essays/`, `artifacts/`) and from operational session metadata (`agent/`).

| Audience | Directory |
|---|---|
| **Community, future committees, contributors** | `meta/` (this directory) |
| **Successor agents, session continuity** | `agent/` (handoffs, rosters, prompts, rubrics, diary) |
| **Checked-in example and historical runs** | `examples/` |
| **Practitioners learning the methodology** | `artifacts/` |
| **Theorists understanding the foundations** | `essays/` |
| **Formalists specifying pipelines** | `palgebra/` |

## Contents

### [project-state.md](project-state.md)

Canonical current-state doc for repo architecture, compatibility truths, open decisions, and any remaining documentation sweep work.

### [research-programs/](../research-programs/README.md)

Research plans, experiment designs, evidence-building programs, and their results are collected in **research-programs/**. Start there if you want to contribute evidence or infrastructure work.

### [methodology-evolution.md](methodology-evolution.md)

How the methodology developed: mistakes made, dead ends explored, patterns that emerged, and a chronological development trajectory from January 29, 2026 through the present.

### [uptake-and-usage.md](uptake-and-usage.md)

External adoption signals: forks, platform integrations, practitioner feedback, and what they suggest about whether the methodology works outside its birthplace.

### [is-author-crackpot.md](is-author-crackpot.md)

Two adversarial committee runs assessing whether the repository's interdisciplinary synthesis is genuine or crackpottery, plus the residual open question about practical value.

### [repository-review-and-run-guide.md](repository-review-and-run-guide.md)

In-depth review of the repo and a concrete run/test guide: what is runnable, how live outputs are organized, and how to validate the repository structurally.

## Why this directory exists

The methodology claims to be self-improving: applying Cyberneutics to itself should produce measurable improvements. This directory is where that claim gets tested and tracked.

Future `/committee` deliberations about project direction should read this directory and `meta/project-state.md` first.
